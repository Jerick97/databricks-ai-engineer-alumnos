## Recuperación016 y checkpoint de captura

`recover_published_capture(project,plan,target,receipt,artifact_store)` reutiliza materialize_release y load_release: verifica original/derivado/pares/curación/modelo y plan completo. Extrae SourceDocument del SK06 publicado; reconstruye tablas SK02 y sellos de extracción en una raíz aislada. Intentos reconstruidos llevan status restored_published y timestamp original, no GET nuevo. Instala local por rename POSIX sólo sobre destino ausente/vacío. No modifica current compartido.

`stage_pending_capture` exporta una transacción lógica SQLite a JSON cerrado (≤4MiB, ≤10000filas/tabla) más originales/derivados, baseline, resultado y backlog; no envía DB/WAL. Files conserva su cap de archivos/bytes/readbacks y write-once. `SnapshotWriter.save_capture_checkpoint` valida guard y request registrado, hashes/readback y base publication, y agrega recibo immutable a ese request mediante CAS; `latest_capture_checkpoint` consulta el de revisión más reciente compatible con current. El receipt es de captura pending, nunca publicación RAG.

`prepare_and_publish` intenta restaurar ese checkpoint en raíz vacía antes del release publicado; `recover_pending_capture` verifica descriptor/manifest/plan/rows/derivados y resultado idempotente. Mismo run restaura pending sin refetch; run nuevo captura desde historial conservado. Reanudar procesamiento requiere un run nuevo y los adaptadores/autorizaciones pendientes; el constructor no habilita modelos. Config driver mantiene capture_mode=remote y ruta local absoluta fuera de /Volumes, que ahora puede ser efímera.

Si Files/CAS falla antes de confirmar recibo, conservar estado local y error: no afirmar durabilidad; retry explícito same-run reutiliza captura. Si una captura interrumpe antes de completar extracción, el checkpoint automático no cubre esas filas parciales. Se conserva localmente ese intento pero puede perderse al desaparecer el host; este límite no debe ocultarse como cobertura completa. Restaurar nunca cambia captured_at ni fabrica frescura. Pruebas son locales con Files/CAS fixtures; pendientes ejecución/autorizaciones cloud y costo observado.
