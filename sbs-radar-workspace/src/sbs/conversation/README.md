# SK07 component v0.1.2

`Conversation(tools=..., generator=..., generator_mode=...).ask(session, question, focus=None)` returns a status, optional SK01 Answer, resolved focus, limitations and trace. `focus` replaces the complete QueryContext; family shifts cannot inherit the previous pair. A missing selected provision for “ese punto” asks for clarification. Natural-language family/pair selection must be resolved by the backend before calling this API; this component does not guess those identities.

The backend must authenticate the actor, bind a Session to that authenticated user, resolve allowed QueryContext, pair, corpus snapshot, original raw texts and processing status server-side. Neither Session nor Tool modes, focus, originals, comparison maps or snapshots may be populated directly from client JSON. Session changes require serialized access per session. `actor` cannot be authenticated by a role written in the question. The backend also enforces request size, transport deadlines, rate limits and source permissions. A shared snapshot label must correspond to an independently verified corpus revision; this code checks equality, not remote provenance. It accepts an explicit tool `conflicts` annotation but does not detect contradictory legal meanings automatically.

`adapters.py` binds the existing `retrieve`, `compare` and `GenieAdapter.ask` APIs. Retrieval requires the real authorized ServerScope and an embedding adapter/index established by SK04/SK05. Reranker failures remain explicit limitations; there is no fixed SQL fallback for Genie. Fixed routes use the user question only, execute at most once per route, and never execute commands returned by PDFs or the generator. Simple keyword routing requires evaluation for paraphrases; no universal intent classifier is claimed.

The generator receives messages containing the versioned skill resource, the local GeneratedClaims schema and a JSON data envelope. No prompt supplied by a runner replaces that resource. The generator cannot supply approval history; impact output remains proposed. SK08 validates trusted original text against all citations before generation and validates the final Answer again. Schema/literal checks do not prove semantic entailment, complete material claim annotation, applicability or current legal force. SK09 evaluation remains required.

Construct `DatabricksGenerator(transport=SingleShotTransport(workspace_client), max_requests=N, max_tokens=M)` with the normally authenticated SDK WorkspaceClient. It posts once using `config.authenticate()`, a finite timeout, no retries, no redirects and no tools. It does not execute during construction. Endpoint: `databricks-gpt-6-sol`; actual response model and usage are recorded. Output cap is per request, not a total input token or cost cap. Keep one instance per authorized run to retain its finite request quota. Streaming is not implemented. Deployment must verify endpoint response behavior; unit transport fixtures do not establish compatibility.

Trace counters distinguish real adapters from fixtures by backend-declared provenance. They count attempted component invocations, not each internal SDK poll or inference request. Trace includes instruction/schema/input hashes and adapter diagnostics. Persist trace via SK11 with backend run identity; this module does not claim immutable run persistence. No cloud inference was executed to build or test this component; no E2E claim.

`ask_many(session, question, focuses=[context_a, context_b])` handles an explicit backend-resolved cross-family request with at most two contexts. It returns separate envelopes and typed Answers, each retaining its own EvidencePack and pair; it never mixes citations across families. It preserves the original session focus. No merged legal synthesis or automatic cross-family context discovery is claimed.

## Independent review fixes v0.1.1

Genie binding now requires `ask_scoped(question, context=resolved_query_context)`. Successful output must include `context` exactly matching the trusted request and literal `scope_verified: true`. The backend must establish this from enforced and verified query/results scope, never copy user/model declarations. Legacy SK06 `ask` is rejected until a scoped adapter is implemented. `Conversation` repeats this check for directly injected tools. A matching corpus snapshot alone is insufficient.

The GeneratedClaims response is structurally validated before field iteration; the server composes and validates the external Answer. A normative response requires nonempty cited material claims; after reference/literal validation the displayed `text` is derived only from those claims. Unannotated free prose is discarded. This closes the empty-claims bypass but does not prove entailment of a claim with a valid citation. Semantic review remains required.

Pure Genie counts/lists without normative evidence return `structured_response_pending` before generation. A separate typed wrapper with query/rows/provenance is pending; this component does not fabricate normative citations for SQL data and does not change SK01. Comparisons and evidence-backed proposals remain available. This limitation prevents a claim of complete conversation functionality.

## Generator migration v0.1.2

The generator callable still receives `{messages, schema}` and returns a JSON object or JSON string. Its output is now exclusively `{"material_claims": [{"text": "Antes: ...", "citation_ids": ["..."]}], "limitations": []}`. The closed local schema is `GeneratedClaims.json`; allowed text labels are `Antes:`, `Después:`, `Cambio:` and `Implicancia propuesta:`. Existing adapters returning complete Answers must migrate; extra fields are rejected. The generic Databricks JSON generator needs no interface change.

The server builds external SK01 Answer from its own answer/context identifiers, immutable original evidence pack, proposed/unreviewed status and merged limitations. It derives displayed text from claims and checks all IDs/literal citations through SK08. The model never repeats pages, offsets, complete citations or EvidencePack in its output. The external Answer schema is unchanged. Label/ID checks constrain structure and cannot establish entailment or legal applicability.
